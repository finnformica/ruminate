### Added

- Give an AI agent your notes, on a leash. **Settings → MCP access** mints tokens for the [Model Context Protocol](https://modelcontextprotocol.io), so Claude or any other client can list, search and read your notes and walk them a block at a time. You tick which of **read**, **write** and **delete** a token gets, whether it reaches every note or only the ones you pick, and when it expires. **Revoke** stops it on its next request.
- Pictures in notes, behind a switch. Paste a screenshot, drop an image file onto the note, or type `/image` on a line, and the picture becomes a block of its own with an optional caption beneath it. Click it to see it full size, or right-click to open, download or delete it like any block. The note keeps only a small reference, so notes stay quick to sync, and `type:image` finds them in search.
- Code blocks. Paste markdown with a fenced block and it becomes a bordered, tinted panel in the mono face that keeps every line and indent exactly, with the language shown top-right. Type three backticks and a language and press <kbd>↵</kbd> to start one, or pick **Code** from the slash menu. Inside it <kbd>↵</kbd> adds a line and <kbd>⇧</kbd> <kbd>↵</kbd> leaves with a fresh block below. Inline code is a bordered chip in the same tint.
- Right-click any block for its menu. It holds **Edit**, **Turn into** (a submenu with the block's current type marked), **Duplicate**, **Collapse** or **Expand**, **Zoom into**, **Copy**, **Copy link to block** and **Delete**, each with its shortcut beside it. On a block held in more than one place it also offers **Unlink**, and **Delete** says how many places it will remove the block from. Right-clicking a row selects it first.
- **Unassigned**: deleting a block no longer deletes everything beneath it. Press <kbd>⌫</kbd> on a block, cut it, or pick **Unlink**, and it leaves the outline for an **Unassigned** section at the foot of the note, still nested as it was, from where it can be pasted back or deleted for good. An empty block with nothing beneath it is simply deleted. Deleting is now always deliberate, and every block remembers the note it was written in.
- Maths in notes. Wrap a formula in double dollars, `$$E = mc^2$$`, and it is typeset in the block; a line that is only a formula is set on its own, centred, in display size. Single dollars stay plain text, so prices are never mistaken for maths. Until now a formula in a note showed as its source.
- Loops. A block can now be pasted beneath one of its own descendants, or beneath itself several levels down: the outline shows the loop where it closes, as a row whose fold arrow is greyed out and will not open, and zooming into that row goes round once more. Only pasting a block directly onto itself is refused. Until now such a paste silently made a copy.
- Choose the app's theme. **Settings → Appearance** now offers System, Light and Dark: pick one and Ruminate keeps it whatever the device is set to, or leave it on System to follow the device as before. The choice is remembered on this device and applied before the page draws, so a dark app never flashes light while it loads.
- The phone nav bar shows when the app needs you. A small dot on the menu button turns red when a sync has failed or your GitHub sign-in has expired, amber when the sign-in is about to expire, and your accent colour when a new version is waiting. Open the menu to see the detail and act on it. Until now a phone could sit on a stale build or a failed sync without a hint.
- Choose how much of a note opens by default. **Settings → Editor** has a **Default expand** slider from 1 to 10: how many levels show beneath a heading or the top of a note before deeper blocks fold. Two is the default, as before. Notes you have never folded follow the slider, so moving it changes them at once.
- Search inside a note with `in:`. Give it a note, by id or by name (`in:"Reading list"`), to limit a query to the blocks in that note, or a block id to limit it to what sits under that block. It composes with everything else, as `type:todo in:"Reading list"` or `-in:…`. Opening <kbd>⌘</kbd> <kbd>K</kbd> inside a note sets it for you, and a pill under the query says so.
- Suggestions for qualifiers as you type. Type `type:`, `in:`, `has:` or `no:` into a search box and a picker opens with what can go there: the block and note types, or your notes by name with the open one first. Keep typing to narrow it, <kbd>↑</kbd> and <kbd>↓</kbd> to move, <kbd>↵</kbd> or <kbd>Tab</kbd> to pick, <kbd>Esc</kbd> to leave what you typed. Screen readers announce each option as you move through it.
- Choose what a new block starts with when you press Enter. **Settings → Editor** has a **New block markdown** field with Bullet, Paragraph, To-do and Quote presets, or type any marker you like. Bullets remain the default, and to-do and numbered items still carry on their own list.
- A slash menu in the editor. Type `/` at the start of a word while editing and a menu opens under the caret: **Today**, **Tomorrow**, **Yesterday**, **Next week** and **Last week** insert that date, and any phrase that reads as a day (`/friday`, `/in 2 weeks`, `/1 oct`) is offered too. Underneath, **Turn into** switches the block's type. Each pick is its own undo step.

### Changed

- Ruminate asks you to update once, and each device then fetches a fresh copy of your notes. A note's root is now stored under the name the app has always used for it, and a copy of Ruminate from before that change cannot read the new rows, so older versions are refused by the server and shown the **Update Ruminate** notice. Anything written offline and never synced goes with the old copy, so sync before you update.
- Notes and blocks are drawn by one row. A note in a search result, in the notes list and under a <kbd>⌘</kbd> <kbd>K</kbd> query is now the row the editor draws a block with, and it opens in place: click the arrow, or press <kbd>→</kbd>, to read the blocks inside it without leaving the list. A note used to be a card, or a flat row, that could only be opened. The notes list is one list now, so the grid switch is gone.
- The notes list and the full results view are the block editor. The keys, the highlight, the folds and the look are the note page's: <kbd>↓</kbd> from the search box lands on the first row, <kbd>space</kbd> folds, <kbd>f</kbd> opens the note at that block. The notes list is browsed, while a filtered view edits in place, so you can tick a to-do you searched for or fix a typo in a heading and have it land in the note.
- Every block lines up in one column, and folding is done from the block's own marker. Bullets show a dot, headings a `#`, numbered items their number, to-dos their checkbox; a paragraph leaves the space empty so its text sits in the same column. Hover the marker of a block with children and it becomes a fold arrow, so reading a block never surfaces any controls. The guide line for the children hangs straight down from that marker.
- A selected block is outlined rather than painted. A thin ring in your accent colour sits around the line over a much fainter tint, in place of the solid coloured band, while hovering still fills a block with a whisper of grey: a fill follows the pointer, a ring marks what the arrow keys will act on. When the editor does not hold the keyboard the ring goes grey, and any key lights it up again.
- Selected rows look the same everywhere. The highlighted block in the editor, the keyboard highlight in the notes list and the current page in the sidebar all share one colour, a paler tint of your chosen accent, so "you are here" reads the same wherever you see it. It follows whichever accent you pick in Settings, in both light and dark mode.
- A selected block's marker takes a tint of the accent too. A heading's `#`, a bullet's dot, a list number and a quote's mark and bar now sit with the highlighted text rather than beside it in plain grey, a shade deeper than their usual colour. Checkboxes and fold arrows keep their own colours. In the sidebar, the open note's icon is filled in and takes the row's tint like its title.
- Choosing something looks the same everywhere, and never looks like hovering it. The theme and new-block-marker pickers and the calendar's current day all mark the chosen one with the accent tint the sidebar uses for the note you have open. Several used to be painted in exactly the shade a control takes when the pointer is over it, so you could not tell what was chosen from what you happened to be pointing at.
- Folding and unfolding a block is animated, like an accordion. Its children fold up into it or unfold beneath it as one piece, with the rows below following, rather than vanishing and reappearing in a blink, and the fold arrow turns in step. The keyboard never waits for the motion: pressing <kbd>space</kbd> repeatedly is as quick as before. With reduced motion switched on, the rows fade instead.
- Keyboard shortcuts are drawn as keycaps everywhere. In tooltips, menu items, the sidebar, the command menu and the search box's hint, a shortcut is now a row of small keys rather than a run of characters, so it reads the same wherever it appears. The sidebar lists the keys beside Notes, Calendar, Settings and Help. Touch screens, which have no keys to press, show none of them.
- A search result looks exactly like the block it is. The filtered view used to draw blocks with its own simplified markers and text styles; results are now drawn by the editor's own row, so a heading has its `#` and its size, a numbered item its number, a quote its bar, and a to-do its checkbox. The full results view shows each block whole rather than clipped to two lines.
- A search result's breadcrumb says only what tells one row from another. It drops the note's icon, which repeated the name beside it, and drops the name itself when every result is in the same note: searching inside one note used to repeat that note's name under every single row. The trail of blocks a result sits under is unchanged.
- Pictures can be resized and set to a side. Hover a picture, or select its row, for a slim handle at its edge: drag it to make the picture narrower or wider, and it stays that fraction of the row on any screen, snapping to full width when you get close. A toolbar in the picture's corner sets whether it sits left, centre or right, and the caption goes with it. Each change is one undo step.
- A pasted picture appears the instant you paste it. The row lands straight away showing the file from your own machine, with a small spinner over it while the bytes go up in the background. Nothing half-made is written to the note: the block carries no reference until the upload succeeds, and a failed upload takes the row back out while a toast says why.
- An image block sits flush. The picture has no frame and starts where the row does, rather than inset where a bullet would be, with an even margin of the row's surface around it; it fills the row's width when it is wide enough and centres itself when it is not. Clicking the empty space beside or beneath a picture selects its block, as clicking text does, and a picture with no caption leaves no empty line beneath it.
- Opening the app on a device that has not pulled your notes yet shows skeletons. A title bar and a few lines appear in the page, and three rows in the sidebar, where the notes are about to be, rather than an empty list or an "Untitled" note that fills in a moment later.
- Notes fit more on a phone. Headings and the note title are smaller on touch screens, while body text keeps its size, block lines sit a little closer together, and the page gutter is narrower, so a paragraph takes fewer lines and more of the note is on screen at once.
- A note's actions button in the sidebar sits inside the note's own row. It appears at the row's end when you hover the note, evenly inset like the fold arrow in a block, and the title shortens with an ellipsis to make room. A separate pill used to appear beside a narrower row.
- The help panel's formatting list is drawn by the note renderer itself, so each example shows exactly what a block will look like. The block markers are listed with the block they make.
- External pictures in notes load straight from their own address. They used to be relayed through the app's server, which would fetch any URL it was given.
- The **Update Ruminate** button appears sooner after a new version ships. A developer diagnostic file was being published with the app and downloaded as part of every update, roughly a third of everything that had to arrive before the button could appear. It is no longer included.
- The block context menu's items no longer carry icons. A few of them (Edit, Copy, Delete) had one and the rest did not.
- A heading's highlight reaches a little further left at the larger sizes. The fold arrow, and the `#` it stands in for, now sits the same distance from the left edge as from the top and bottom. The text itself does not move.

### Removed

- Tags are gone. The tags page, the sidebar's **Tags** entry and its shortcut, the tag pills and filter above the notes list, the `tag:` and `tags:` qualifiers, the `#tag` line in the help panel, and the agent's tag tools and filters have all been removed. A `#word` in a block is plain text, as it has rendered for a while. Nothing is deleted from your notes: a `tags` entry a note already carries stays where it is, simply no longer read.
- Frontmatter. A note's metadata — its title, pin, font, width and the date it changed — lives on the note itself, never as a `---` block in its text. Copying a note as markdown now gives you its blocks only, and pasting markdown that starts with such a block drops it instead of turning its lines into blocks.
- Sharing a note as a GitHub gist. The **Share** item, the publish dialog, the public `/share/…` page and the "published" globe are gone; gists you already published stay on your GitHub account, but their share links no longer render. Signing in now asks GitHub for your email only, not gist access.
- Four holdovers from the app's origins. They are the dice button that opened a random note; a note taking its icon from a `url` or `github` property or a leading emoji in its title; the `birthday` property, which put a person's next birthday on the calendar; and the `!!1` priority markers, which nothing had displayed for some time.
- The **Forget my folds on this device** button in Settings → Editor, and the paragraph beneath the expand slider. Folds are still kept for each note on this device exactly as before; there is simply no button to clear them.

### Fixed

- A sign-in on a version of Ruminate too old to talk to the server no longer fails silently. Pushes and pulls used to quietly stop while the app kept looking like it was syncing. The page now says so, with an **Update Ruminate** button that does the same as the sidebar's, and everything you write meanwhile stays on the device and syncs once you have updated.
- Copying a block and pasting it onto another block in the same note now links it there. The note holds the one block in two places, and editing either row changes both, exactly as pasting into another note has always worked; it used to make an independent copy. Pasting a block onto itself is refused, with a toast, as is pressing Enter in the middle of a block that lives in several places.
- Unfolding a block with a picture among its children no longer jumps. A picture's row took its space only once the picture had loaded, so the unfold measured the nest without it and everything below jumped as the picture arrived. A picture whose size is known now has its space from the first frame, so the unfold sweeps down over the whole nest.
- On a phone, press and hold a block to open its menu. The menu opened on a right-click and a long press alike, but on a phone it came up empty: a long press never tells the page which block was pressed the way a right-click does. It now works out the row from where the finger is, and the row's text no longer starts a text selection underneath it.
- On a phone, a long link or an unbroken word no longer runs off the edge of the screen. It wraps within the block, in both reading and editing, and so does a long note title, rather than forcing the page to scroll sideways. A block's text is also shown exactly as stored, so a leading `-`, `#` or `>` that the renderer used to swallow now stays visible and a badly migrated line can be put right.
- Installed to an iPhone's home screen, the phone nav bar sits where it should. It is at the bottom of the screen, just above the home indicator, rather than floating above a band of empty space or hanging half off the bottom. In a home-screen app iOS reports every viewport unit wrongly, so the app now takes its height from the document itself. In a browser tab nothing changes.
- Copying blocks gives tighter, truer markdown. A heading or paragraph nested under a bullet stays indented under it rather than dropping to the margin, and a blank line is written only where markdown would otherwise merge two blocks, so a quote followed by a list no longer has an empty line between them and nothing trails at the end.
- Pasting an outline keeps every glyph. Markdown where each line is a bullet carrying another marker — `- # Heading`, `- > quote`, `- [ ] task`, the shape most outliners export — used to keep the bullet and leave the `#` or `>` as literal text. The inner marker is now the block's type and the bullet is dropped, so a pasted heading is a heading and a pasted quote a quote.
- Editing a picture's caption no longer clips it to one line. A caption long enough to wrap shows every line while you type it, as it does once you stop.
- The `/` menu is frosted like the command palette again. It had turned see-through: the page column's scroll fade was a mask, and a mask on an ancestor makes browsers drop a descendant's backdrop blur. The fade is now painted over the column's top edge instead.
