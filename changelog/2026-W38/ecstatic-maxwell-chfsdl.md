### Added

- A note can now be filtered and sorted where it stands. **Filter** and **Sort** sit beside the **⋯** menu at the top right, and what they set narrows the note itself rather than sending you to a list of results: the rows that match stay, the headings above them stay as dimmed context so you can see where each lives, and the branches holding nothing you asked for go. It is the note, shorter — the same bullets, the same keys — so a list of unticked boxes is one pick, and ticking one still ticks it.
- A note's filter understands the whole query language, because the search engine answers it. `type:`, `in:`, `has:`, a property, `-` and comma lists mean in a note's **Filter** what they mean in the search box. The menu lists block types, from the box's own list; the rest of the language is about the note rather than its rows, so inside one note it shows everything or nothing and is better typed than offered.
- A filtered note is a link. The filter and the sort live in the address, so a narrowed view can be bookmarked and shared, and the back button takes it off again. Both are written in the same [query language](/docs/query-language.md) the search box speaks (`type:todo`), so what the menus set can be read, and typed, by hand.
- Any note, and any block, can remember a filter and a sort as its **default view**, so it opens the way you left it — nothing needs pinning. The save is deliberate: narrow a note and a dot appears on the button that moved, whose menu grows a footer offering **Update to default** and **Reset to default**. The dot says which half moved; the buttons settle the whole view, so saving from **Sort** keeps the filter you had set.
