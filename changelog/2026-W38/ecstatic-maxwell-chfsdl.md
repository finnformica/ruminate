### Added

- A note can now be filtered and sorted where it stands. **Filter** and **Sort** sit beside the **⋯** menu at the top right, and what they set narrows the note itself rather than sending you to a list of results: the rows that match stay, the headings above them stay as dimmed context so you can see where each lives, and the branches holding nothing you asked for go. It is the note, shorter — the same bullets, the same keys — so a list of unticked boxes is one pick, and ticking one still ticks it.
- A note's filter understands the whole query language, because the search engine is what answers it. `type:` on the block, `in:` on its ancestry, `has:`, `no:`, `date:`, a property, `-` to exclude and comma lists to OR all mean in a note's **Filter** exactly what they mean in the search box, and the menu offers the same keys and values the box's picker offers — so neither can drift from the other. `sort:` gained two keys along the way, `text` and `type`, which order blocks by their own text and type in search as well.
- A filtered note is a link. The filter and the sort live in the address, so a narrowed view can be bookmarked and shared, and the back button takes it off again. Both are written in the same [query language](/docs/query-language.md) the search box speaks (`type:todo`), so what the menus set can be read, and typed, by hand.
- A pinned note or block can remember a filter and a sort, so a pin can be "the open to-dos under this heading" rather than just the heading. Opening it from the sidebar brings that view back. The save is deliberate: change a pinned block's filter and a dot appears on the button that moved, whose menu grows a footer offering **Update to default** and **Reset to default**. The dot says which half moved; the buttons settle the whole view, so saving from **Sort** keeps the filter you had set.
