### Added

- A pill of actions floats above the keyboard while you edit on a touch screen. **Aa** opens bold, italic, strikethrough, code, link and maths, each drawn as it renders; **Turn into** opens the block types as their markdown glyphs; then **Outdent**, **Indent**, **Undo**, **Redo**, **Image** where pictures are on, **Delete**, and a button that puts the keyboard away. See docs/mobile.md.
- Formatting has keyboard shortcuts while you are editing a block. <kbd>⌘</kbd> <kbd>B</kbd>, <kbd>⌘</kbd> <kbd>I</kbd>, <kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>X</kbd>, <kbd>⌘</kbd> <kbd>E</kbd>, <kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>K</kbd> and <kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>M</kbd> wrap the selection in bold, italic, strikethrough, code, a link or maths, and take it off again.
- Share a note with another Ruminate user. Choose **Share…** in a note's **⋯** menu, or on a block, give the email address they sign in to GitHub with, and say whether they may edit and delete as well as read. Everything under a shared note goes with it, including blocks you add later. Shared notes appear in your sidebar under **Shared**. **Settings → Sharing** lists what you have shared and what has been shared with you, with a Revoke that takes effect at once.
- Links get names. Paste an address and it becomes a link named for its host, `[example.com](https://www.example.com/a?b=1)`, with the address kept whole. Hover any link for a card with the address, a copy button and **Edit**, which changes the URL or the title, or removes the link. An address you type is named the same way once you type a space after it, and needs no `https://`. See docs/links.md.
- Link blocks: a link as a card of its own, carrying the page's preview. Hover a link and choose **Turn into block** for a card of the page's title, description, favicon and picture, fetched once and kept on the block so the note opens offline. Double-click the card to edit its title. Drag the handle at its side to narrow it, or align it as you would a picture. `type:link` finds them. See docs/links.md.
- Pin a block. **Pin** in a block's right-click menu lists it in the sidebar under **Pinned**, between your notes and the ones shared with you. The row opens the note zoomed into that block, and its **⋯** menu unpins it or copies a link to it. A pinned block wears the pin glyph in the editor, and <kbd>⌘</kbd> <kbd>K</kbd> lists pinned blocks after pinned notes. Pinning a note is unchanged.
- Code blocks are syntax-highlighted for their language. The language is the word after the fence — `ts`, `python` — or **Code** from the slash menu with the language typed after. Thirty-odd languages are known by their usual short names (js, ts, py, sh, rs, go, yml, md, html…), and one with no grammar stays plain. Click the language in the panel's corner to change it afterwards. The colours follow the theme and go to plain ink in print.
- A backtick and a space at the start of a block turns it into a code block. It works the way `- ` makes a bullet or `# ` a heading, and in select mode <kbd>`</kbd> toggles one. A marker typed on its own into an empty code block turns it back into that type, so a `# `or`- ` that begins your code stays code. <kbd>⌫</kbd> at the start of a code block still makes it a paragraph.
- Headings fold by default, like any other block. The **Default expand** slider now counts every level from the top of the note, so a note of a heading, a sub-heading and the lists beneath opens at the default of two as just its two rows of headings. Until now a heading was always open and restarted the count beneath it. Notes you have already folded on this device keep your folds.
- An agent can fetch your pictures. The agent tools showed an image block as a caption and an id, with no way to reach the bytes. A new `get_image` tool hands back a download link that lasts fifteen minutes and is bound to the token that minted it, so revoking the token kills its links too. The bytes are never embedded in a tool result. See docs/mcp-server.md.

### Changed

- On a touch screen, one tap on a block edits it. The tap opens the whole row rather than just the word under it, with the caret where it landed, where it used to take a double tap. A press and hold still opens the block's menu. Putting the keyboard away ends the edit and leaves the block highlighted, and the fold chevron and the bullet's zoom target are larger under a finger.
- The **Default expand** setting applies to every row you have not folded yourself, in every note, whenever you change it. It used to decide a note only the first time you opened it on a device, after which the note was on its own. A row you opened stays open when the setting moves, and a row you closed stays closed as the note grows around it.
- Zoomed into a block, the folds you make belong to the zoomed view. Zooming out opens the way back to the block you were in, so you land on it.
- A large note opens faster. It is now walked only as far as its open rows, so what sits beneath a fold is not built until you open it. Nothing looks any different.
- <kbd>⌘</kbd> <kbd>K</kbd> searches everything, not just the note you are in. It used to add an `in:` scope of the open note, or of the block you had zoomed into, to everything you typed, so a search from inside a note never found anything elsewhere. To look inside the open note, type `in:` and pick it: it leads the suggestions as "this note".
- The query's filters are pills, not text. Finish typing a qualifier (`type:todo`, `in:`, `-type:done`, `sort:updated`) and it leaves the line for a pill beneath the box, so the line holds only the words you are searching for. Click a pill to take the filter out, or press <kbd>⌫</kbd> on an empty line to take the last one back to edit. The `?query=` URL and what the search runs are unchanged.
- <kbd>⌘</kbd> <kbd>P</kbd> is the <kbd>⌘</kbd> <kbd>K</kbd> palette with two pills already set. They are `type:heading` and `in:` the open note, so the results are that note's headings in order; typing narrows them, and <kbd>↵</kbd> on one opens the note zoomed into it. Take the pills off and it is the ordinary search.
- Search works the same wherever you meet it. The notes page, a filtered view and <kbd>⌘</kbd> <kbd>K</kbd> share one query box and one results block: the same count line, the same rows, the same pause before a search runs, the same words when nothing matches. In the palette, <kbd>↵</kbd> straight after typing opens the full results view, and <kbd>↵</kbd> on an item you have arrowed to opens that item.
- Results are ranked purely by how well they match. A note whose title matches is a row among the matching blocks rather than in a group above them, so a block that matched better comes first. The count says how many notes matched by title. A query for a block type (`type:todo`), or one scoped with `in:`, lists blocks only.
- With nothing typed, <kbd>⌘</kbd> <kbd>K</kbd> shows **Recent** and **Pinned**. Recent is the five notes you most recently touched: edited or created on any device, or opened, typed into or zoomed into on this one. Merely reading a note never counts. Pinned lists your pinned notes, less any already shown as recent. Both give way to results the moment you type.
- Qualifier values open in a popover beside what you are typing. Type `type:`, `in:`, `has:`, `no:`, `sort:` or `date:` and the choices appear next to the token, on the notes page and in <kbd>⌘</kbd> <kbd>K</kbd> alike, rather than as rows added into the palette. Keep typing to narrow, <kbd>↑</kbd> and <kbd>↓</kbd> to move, <kbd>↵</kbd> to pick. On a phone it takes the full width of the box.
- The suggestions popover is just its rows. The header that repeated the qualifier, the key hints beside it and the gloss on every row are gone; a block type sits beside its markdown glyph, a note type beside its icon, and every row is capitalised. `sort:` is picked in two steps and lands written in full, as `sort:title:asc`.
- A heading listed as a result is drawn as a row among many. It is bold, at the body's size and level with the note rows beside it, with none of a heading's breathing room above. It used to appear at its full in-note size, so a pinned heading towered over the Recent list.
- The palette starts empty each time it opens. The query goes with the dialog.
- The sidebar's sync status says **Offline** when the device has no network. It used to disappear, leaving a separate Offline row above it. Hover it and it says your notes are saved on this device and will sync once you are back online. Offline, Ruminate no longer tries to push or pull at all, so coming back online no longer flashes **Sync failed** for a push that could never have landed.
- Zoomed into a block, that block is the page's title. It is drawn exactly as a note's title is: at the title's size with the `#` beside it, above its children, in place of the block's own row. <kbd>↑</kbd> from the first block highlights it and <kbd>↓</kbd> returns, and <kbd>Enter</kbd> edits its text as one undo step. A code block or a picture reads as the title but is edited in its own row, zoomed out.
- A note's title no longer lines up with the blocks beneath it. On a wide page the title, the breadcrumb trail and a zoomed block's title sit further out towards the page's edge, with the title's `#` in the margin beside it, so the outline reads as indented under its heading. The blocks themselves have not moved, and on a narrow page the title keeps its old place.
- Code highlighting is stronger in dark mode. Its four syntax hues were the near-white text steps and now sit at the same saturated step the light scheme uses. In both schemes more of the code is picked out: numbers, types, class names, constants, regexes and template literals.
- **Settings → Sharing** leads each row with what was shared. A share you have given shows the note, or the block as _Note › text_, with the address beneath it; a share you have received shows the note or block, with who shared it beneath. It used to lead with the address, so you could not tell which note a shared block came from.
- Notes shared with you are one list in the sidebar, under **Shared**, rather than a list for each person. Who shared a note is its row's tooltip, and the note's header says it too, as a quieter first crumb before the title: _John Smith › My Note_.
- An agent searches with the words you do. The agent `search` tool used to look for a case-insensitive substring; it now takes the same query language you type in the search box, including `in:`, `type:todo`, `-type:done`, `a,b` for either, `sort:updated` and free text. Each hit names the block, its note and the heading it sits under. Nothing about who can see what changes.
- A bullet list carries on as bullets. <kbd>↵</kbd> at the end of a bullet now makes another bullet whatever **New block markdown** (Settings → Editor) is set to; it used to make the setting's block instead, so with the setting on plain text a list stopped after one item. To leave a list, press <kbd>↵</kbd> on an empty item.

### Removed

- The palette's outline mode. That is `@` typed first in <kbd>⌘</kbd> <kbd>K</kbd> to list headings, the live preview that highlighted and scrolled the note behind the dialog, and <kbd>⌫</kbd> on an empty query to leave the mode. Headings are searched with `type:heading` now, which <kbd>⌘</kbd> <kbd>P</kbd> sets for you, and a result opens the note at the heading.
- <kbd>⌘</kbd> <kbd>K</kbd> no longer lists **Jump to** or **Note actions**. The jumps have their own keys (<kbd>g</kbd> then <kbd>n</kbd>, <kbd>d</kbd> or <kbd>s</kbd>) and the sidebar, and the note actions live in the note's own menu. The palette is for finding notes and blocks: with nothing typed it shows Recent and Pinned, and <kbd>↓</kbd> goes straight to the first row.
- The `?heading=` address on a note, which highlighted a heading by its text. Nothing had written it for some time. A link to a block is `?block=`.

### Fixed

- Naming a new note now creates it, and a new note opens with its title ready to type. The name you typed was thrown away on <kbd>↵</kbd>, because only a first block could bring the note into being, so you had to write a block first and name the note afterwards. <kbd>↵</kbd> in the title now carries on into a block below it. That holds when renaming any note.
- Switching to another tab no longer closes the block you were typing in. Losing the window's focus was taken as you leaving the block, so on your return the caret was gone and the block had to be opened again. The field now tells the window going from focus moving elsewhere in the page. A click elsewhere still ends the edit, and a note's title behaves the same way.
- Typing in <kbd>⌘</kbd> <kbd>K</kbd> no longer loses the keyboard to the results. Each letter you typed changed the rows beneath the query, and the rows took the focus as they changed, so the next letter went to them and your search stopped mid-word. The rows now take the keyboard only when you press <kbd>↓</kbd> into them, and the same rule holds on the notes page.
- Typing in a block no longer drops you out of it after one character. When a note had an **Unassigned** basket beneath its outline, every keystroke changed the basket too, and the basket then took the keyboard back for its own highlighted row. An editor now takes the keyboard only when nothing else holds it, so the block you are typing in keeps it, as do a note's title and a dialog's field.
- Right-clicking inside the block you are typing in shows the browser's own menu. A misspelt word's suggestions, and cut, copy and paste, are there as in any text field; the block's menu used to open over it and swallow them. The block's menu still opens on a right-click anywhere else on the row.
- Reading a note shared with you is far cheaper. Finding everything beneath a shared note used to scan the owner's whole set of links once for every block it reached, on every focus, tab switch and reconnect, which spent most of a day's cloud budget in a morning. It now seeks each block's links directly. The same fix reaches the agent tools that walked the same way.
- A note shared with you now reads like your own. The arrow keys move through its blocks, a click highlights one, <kbd>space</kbd>, <kbd>←</kbd> and <kbd>→</kbd> fold and unfold, and <kbd>f</kbd> zooms in. It opens folded to your **Expanded levels** setting, with your folds kept on this device as for any note. It used to open with nothing highlighted and answer no key. Only editing is off.
- A shared note's title looks and behaves like your own notes' again. That is the hanging `#`, the alignment with the blocks beneath, the highlight when you arrow up from the first block, and <kbd>↓</kbd> back into the note. It had been drawn as a plain heading with none of those. Only renaming stays off.
- A copied picture says so wherever it is pasted. Slack, the Claude chat and other apps that take the rich-text flavour of the clipboard drop a picture they cannot load, and dropped its caption with it, so a copied note lost every trace of its pictures. A picture now travels as a figure with a caption beneath, `[image: caption]`, which those apps keep. Nothing is downloaded at copy time.
- Pictures in pasted web content come in. HTML pasted from a web page used to drop its `<img>` tags; each is now an image block, captioned from its alt text, showing the picture from where it is. A picture copied out of Ruminate reads back as the upload it was.
- A copied to-do keeps its box when pasted elsewhere. The box was written as a checkbox control, which Slack, the Claude chat and other rich-text composers drop on paste, so `- [ ] task` arrived as a bullet with a stray space. The box is now the `[ ]` or `[x]` text itself, which every app keeps, and which still reads as a task where markdown is understood.
- A pinned block's pin no longer hugs the row's right edge. It sits in a slot of its own that mirrors the marker's on the left — the same width, on the first line, the glyph centred — so it is as far from the edge as a bullet's dot is. A heading's highlight, which already reached further out on the left, now reaches as far on the right.
- The last block in the **Unassigned** basket can be deleted. <kbd>⌫</kbd> on it, and the menu's **Delete**, did nothing: the rule that keeps a note from losing its only block applied to the basket as well, where the last row going is the whole point, and the basket goes with it. The outline keeps the rule.
- Code blocks are the same shape as every other row, and editing one no longer moves anything. The panel used to hang off the text column, with its padding and border on the text field itself, so an empty block had no room for its caret and jumped to size on the first keystroke. The panel is now the row's own surface, and inline code is a rounded chip again.
